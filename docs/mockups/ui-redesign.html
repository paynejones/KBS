Design exploration

Calmer surfaces, clearer next steps

Five mockups for KBS: the same features, retuned for faster scanning and fewer competing controls. Status becomes colour, actions collapse into menus, and every screen has exactly one obvious primary action.

01

One primary action

A single filled button per screen. Everything else is quiet until needed.

02

Colour means status

Indigo is reserved for interaction. Green, amber and blue only ever label state.

03

Hover, don't shout

Row actions appear on hover as one menu, so density stays readable.

04

Keyboard-first

Search sits at the top of the sidebar and teaches ⌘K on sight.

01

Home — resume, don't browse

Today the home page stacks a hero, recents, pinned widgets and a "Recently updated" grid. This version merges them into one hierarchy: resume card row → recent pages → pinned views.

Why it works

1
One filled button

"New page" is the only primary. Quick find and templates stay quiet, so the page has a single focal point.

2
Resume, not recall

Cards carry a two-line snippet and edit time. Replaces "Jump back in" rows that all looked identical.

3
One canvas of sections

Recents and pinned views sit side by side instead of being three full-width stacks with the same weight.

4
Search where the eye starts

The sidebar search field doubles as a ⌘K advertisement; the header loses one floating button.

5
Status is a pill

Widget rows use colour-coded state instead of plain text values from the select property.

6
Fewer hover icons

Page tree rows collapse four action icons into one ··· menu; drag-to-move remains.

Why it works

1
Cover and icon carry identity

Emoji cover and title sit above the toolbar, so the page reads as a document, not a form. The columns stay at a 68-character measure.

2
Properties in a rail

Status, owner, due and tags become glanceable metadata rather than a block wedged under the title.

3
Selection-only floating bar

The toolbar is a quiet sticky strip; formatting also appears at the selection, which is where the cursor already is.

4
Backlinks promoted

"Linked mentions" moves beside the page with an excerpt, instead of being a footer after 2,000 words.

5
Explicit save state

"Saved just now" with a green dot answers the question a blank header leaves open.

6
Type scale with three levels

Title 23, section 14, body 12 in the mockup (24/15/16px at real size) — headings stop competing with body copy.

Why it works

1
Pills replace native selects

Status and multi-select cells render as coloured chips, opened by a small picker on click. They scan in a column instead of reading as form inputs.

2
Column types drive alignment

Numbers right-align with tabular figures, dates stay short, checkboxes centre, and relation/tag cells use chips with overflow counts.

3
Sticky name column

Name pins while properties scroll, so wide databases never lose the row label.

4
One ＋ for new views

Board, Gallery and Calendar move into an add-view menu, replacing three separate buttons that competed with the view tabs.

5
Inline add row

The empty bottom row is the fastest way to enter several records; Enter saves and opens the next.

6
Filter state is visible

Active filters and sorts show as removable chips above the table, so a short list never looks like missing data.

04

Command palette — grouped and self-explaining

Recents, destinations and actions are separated into labelled groups, with the selected row carrying the accent and its shortcut on show.

Why it works

1
Three labelled groups

Recent → destinations → actions. The order matches intent: return somewhere, go somewhere, do something.

2
Every row explains itself

Edit time, record count or unread badge sits on the right, so results are distinguishable before opening them.

3
Selection is unmistakable

One brand-tinted row with an ↵ hint — no ambiguity between hover and keyboard focus.

4
Shortcuts are taught in place

⌘N and ⌘⇧L appear on their commands, which is how people learn them without a settings page.

Four destinations

Why it works

1
Reorder where you see it

A grip appears on the row you hover; the editor repeats the list with arrow buttons so keyboard and touch users never have to drag.

2
The bar is a choice, not a squeeze

Four destinations are picked, not reordered — nine reorderable tabs would keep the 43px targets the mockups are trying to fix.

3
You can never lose your place

When the current route is not one of the four, it is appended to the bar, so the active destination is always visible.

4
One click back

Reset restores the default order. The preference is per device, alongside the theme and recent pages, not a new workspace setting.

5
Pages stay separate

Sidebar destinations and the page tree keep different drag rules, so reordering a page never silently reorders navigation.

Notes — static HTML and CSS, no app code touched. Colours mirror the existing token set so the concepts can be ported screen by screen.
